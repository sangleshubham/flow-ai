# 0061 — Concept-pass gaps do not block whole-book illustration

- Status: accepted
- Date: 2026-10-21
- Workstream: W3
- Spec sections: §6 phase B, §9, §15; amends ADR 0057 decision 2

## Context

[ADR 0057](0057-whole-book-illustration.md) requires the concept pass to finish before a whole-book run plans sections. It already permits completion with failed indexer batches, but their failure set lived only in memory and was cleared on every `start()`. A glossary or book-summary schema, timeout, or upstream error instead stopped the pass before `indexStatus = 'complete'`. Resume repeated that step and the book stayed at “Understanding the book…”.

The section pipeline also automatically requests `indexNow()` for missing indexes. Retrying remembered failures on that path would recreate the same loop during illustration even if `start()` skipped them. [ADR 0058](0058-concept-pass-on-gpt-6-luna.md) keeps the indexer's single escalation; this decision changes failure handling, not model selection or effort.

## Decision

1. **Complete means usable with recorded gaps.** A `schema`, `timeout`, or `upstream` failure in glossary merging or book summarization records the missing step and allows the remaining work to continue. Each failed optional step is attempted at most once until an explicit retry. When no pending sections remain and the transient-batch limit has not been reached, the pass marks the book `complete`, even with index or optional-context gaps. No placeholder summary or glossary is written; context assembly naturally omits missing data. Earlier successfully stored context remains usable if a later refresh fails.
2. **Persist content gaps per book through the existing repositories.** The settings key returned by `conceptPassStateKey(bookId)`, `conceptPass:<bookId>`, stores a versioned record containing the structural `indexVersion`, failed section IDs, and optional-step gaps with error codes and messages. An indexer section is added to the persisted failure list only when escalation fails with `schema` or a successful response omits that section. Failed batch IDs and successful section indexes are persisted in the same transaction. Final `upstream` or `timeout` indexer failures instead enter an in-memory `skippedThisRun` set, settle their section waiters with `false`, and are excluded from pending work for that run; they are never added to persisted failures. Optional glossary and summary transient errors remain persisted gaps. Malformed settings are checked before use; records from another structural index version are ignored. Sections that no longer exist or have since been indexed are removed from the failure list when a pass resumes. `resetConceptPassState(repos, bookId)` deletes the settings key for an explicit re-index, which can retain the same book ID and structural index version. No shared schema or database migration is needed.
3. **Resume retries temporary skips, while content gaps require explicit retry.** `start()` clears `skippedThisRun` and the transient-batch counter, continuing unfinished work while preserving persisted failures across pass instances and book reopenings. Automatic `indexNow(sectionId)` returns `false` immediately for a persisted failure, allowing section illustration with partial context. An explicit `retryGaps()` starts a later pass over persisted gaps; `indexNow(sectionId, { retryFailed: true })` retries one section. Each retry uses the existing indexer attempt plus one escalation, and persists any remaining schema failures or omitted sections again. `retryGaps()` waits until all intervening runs have settled, then reserves its run before awaiting the reset; if there are no persisted failures or optional gaps, it returns progress without model calls or a book-status change. Filling index gaps refreshes the final glossary and summary; a still-recorded optional gap requires explicit retry. `ConceptPassGap` is the public type for optional glossary and summary gaps.
4. **Blocking errors and sustained indexer outages pause the run.** Usage limits retain `paused-limit` and reset information. Authentication, sign-in failures, and abort still pause. `MAX_TRANSIENT_BATCHES_IN_A_ROW = 3` bounds consecutive batches whose initial and escalation calls both fail with `upstream` or `timeout`; a batch indexing at least one section resets the counter. At the limit, the pass stops with `done: false` and the transient error, leaving temporary skips eligible for the next `start()` without `retryGaps()`. The whole-book run pauses with `stoppedBy` on an incomplete pass returning `upstream` or `timeout`, so offline/client-network errors cannot be mistaken for permanent content failures. An incomplete pass without an error remains a pause, including the external offline/pause path. Schema errors and completed passes with optional gaps permit illustration with partial context. Unexpected programming or persistence errors still reject; they are not converted into content gaps. The section pipeline's existing repeated transient-error pause policy from ADR 0057 is unchanged.
5. **Report each completed model call.** Successful and failed indexer attempts, including escalation, glossary calls, and summary calls invoke the progress callback. Successful writes and recorded gaps are visible before their reports. A final report announces usable completion. Glossary and summary reports may repeat the indexed-section count, since those calls do not index sections.

## Consequences

- Whole-book illustration proceeds for all target sections, including failed index batches, with whatever grounded context is available. This relaxes ADR 0057's requirement for glossary and summary success before planning.
- Resume no longer consumes requests retrying persisted content failures. Filling them requires an explicit later pass through the package API; transiently skipped indexer sections are retried on normal Resume. This change adds no reader UI controls.
- apps/reader reindex() (W9) must call resetConceptPassState after deleting sectionIndex; follow-up unit.
- Existing plan cache keys do not include glossary or summary content. Plans generated with partial context remain cacheable; repairing context alone does not regenerate those plans. Explicit regeneration is needed to incorporate repaired context into existing plans.
- The concept pass now requires the existing settings repository as part of `ConceptRepos`. Shared `BookMeta`, index-status, and model-output schemas stay unchanged.
- `packages/illus-concepts/test/pass.test.ts` covers gap completion, persistence, transient outage recovery, explicit retries and their no-op/concurrency behavior, state reset for re-indexing, automatic lookup suppression, per-call progress, public gap typing, and blocking errors. `packages/illus-pipeline/test/book-run.test.ts` covers run readiness, incomplete transient-error pauses, and a real concept pass with indexer, glossary, and summary gaps. All tests use local fakes or replay, with no live model calls.
